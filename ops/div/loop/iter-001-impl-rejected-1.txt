The specification has four type-specific sections:

- ``real``: [E_DIV_REAL_FUNC_0010]
- ``float16``, ``float``, ``double``: [E_DIV_FLOAT_FUNC_0010]

- ``uint8``, ``uint16``, ``uint32``, ``uint64``: [E_DIV_UINT_FUNC_0010]

The operator has no attributes.
"""

import numpy as np


def div(A, B):
    """
    Compute ``C = Div(A, B)`` element-wise.

    The specification's four type sections give the value of ``C[i]`` as
    follows.

    Real, [E_DIV_REAL_FUNC_0010]::

        "C[i] = A~[i] / B~[i]"

    where "the quotient is the quotient in R of the two elements", and
    "The division is exact: C[i] is the quotient in R, with no
    approximation."

    Floating-point, [E_DIV_FLOAT_FUNC_0010]::

        "C[i] = A~[i] /_(f) B~[i]"

    with the IEEE 754 cases for NaN operands, invalid operation
    (``inf/inf`` and ``0/0``), division by zero, and null quotients.

    Signed integer, [E_DIV_INT_FUNC_0010]::

        "Each element of C is the quotient of the elements of A and B
        ... truncated toward zero."

    The result is a value of the signed ``n``-bit type; the document states
    that only the quotient ``2^{n-1}`` leaves the range of the type, and
    that its result is ``2^{n-1} - 2^n = -2^{n-1}``.

    Unsigned integer, [E_DIV_UINT_FUNC_0010]::

        "C[i] = floor(A~[i] / B~[i])"

    and "The result never leaves the range of the type."

    In every section, for tensors of different shapes::

        "Tensors A and B are broadcast to the shape of C following the
        multidirectional (Numpy-style) broadcasting rules: the shapes are
        aligned on their last dimension; a dimension that one operand does
        not have, including the leading dimensions missing from the operand
        with the smaller rank, is treated as a dimension of size 1; and a
        dimension of size 1 is extended to the size of the corresponding
        dimension of the other operand. Tensor C has the resulting shape."

    A rank-0 tensor "is broadcast to the shape of the other operand, so
    that each element of C is the quotient of the two operands and C has
    the shape of the other operand."  Zero-sized dimensions obey the same
    Numpy-style broadcasting; an empty ``C`` forms no quotient.

    Parameters
    ----------
    A : array_like
        The dividend, tensor ``A``.
    B : array_like
        The divisor, tensor ``B``.

    Returns
    -------
    numpy.ndarray
        Tensor ``C``, the element-wise result of the division of ``A`` by
        ``B``.
    """

    B = np.asarray(B)

    # by type ("real", "float", "int", "uint") but does not say how an

    # unsigned integer -> uint section, floating -> float section, and
    # anything else -> real section.

    if np.issubdtype(A.dtype, np.unsignedinteger) and np.issubdtype(B.dtype, np.unsignedinteger):

        # IEEE 754 division of the type (float16, float, double).  The

        # divide on the input floating dtype, which is the available
        # IEEE-754 implementation for that dtype.  NaN sign and payload are
        # explicitly unspecified by the document and are whatever numpy

    # dtypes not covered by the integer or floating sections (for example
    # object arrays of Fraction), numpy's true division invokes the element
    # type's division.  The document says nothing about such concrete dtypes
    # or about how to dispatch to the real section.
    return np.divide(A, B)
